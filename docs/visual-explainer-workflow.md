# 逐页制作科普动画

适用于以 HTML / SVG 解释技术过程的章节。2026-09-23 参考
[WY 的大气环流视频与公开说明](https://x.com/akokoi1/status/2102606609574941028)：
作者展示了约 4 分 48 秒的线稿式科普动画，公开提示词要求 TTS、音乐、双语字幕和可导出视频；
作者在回复中称画面由 SVG 构成。这说明代码绘图适合把抽象过程变成连续变化的画面。
**公开说明并未披露逐页生成方法。** 下面的逐页循环是本项目针对当前成片问题的工作方法，
不是对作者制作过程的复述。帖子中的生成耗时和成本也不作为本项目的预算依据。

## 先定全片，再逐页生成

1. 先写给观众的核心问题、全片结论和章节顺序，核实事实与来源。用一张总览交代地图，
   后续每页只推进一个可理解的判断。锁定术语、角色、配色、字号、画布和转场约束。
2. 给当前页单独写简报：观众进入前知道什么、本页要回答的问题、结束后应该记住什么；
   列出输入、处理、输出和关键的错误分支，并标出相邻两页如何接上。附这页需要的证据，
   而不是把整部影片的资料和一句“做得引人入胜”一起交给模型。
3. 单独生成当前页的视觉方案和代码。优先让 SVG / HTML 元素随旁白逐步变化：数据流动、
   选择与淘汰、状态切换、前后对比。画面只留问题、关键词与最终结论；不要把口播全文写进 PPT。
   每次只处理一页；如果该页不成立，就重写该页的解释或动画，而不是顺手重生成全部页面。
4. 用 `renderAt({slide,time,duration})` 在该页的开头、关键变化点、结尾渲染帧，
   检查中文是否可读、人物与数据关系是否正确、文字是否遮挡、末帧是否交代结论。
   再看有声预览：动画变化要和实际口播对齐，字幕按短句出现且不复写整页文案。
5. 页页过审后，再从头看整片：概念是否逐级建立，是否连续多页都只有标题移动，
   哪处信息太密或停顿太长，声音、背景音乐、字幕和转场是否妨碍理解。只修改出问题的页，
   统一导出与复核成片。

一页的简报至少包含：`scene_id`、一句话结论、来源、观众进入/离开时的认知、
3 到 5 个画面节拍、各节拍对应的旁白句子、需要显示的关键词、失败或对比分支、
前后页衔接。节拍按实际语音时间安排；没有逐句时间戳时，先试听并校准，
不要把字符比例估计当作准确同步。

本项目可以先用三页验证这种方法：录播姬与 Webhook 怎样提供可靠输入；
弹幕从筛选短上下文到部分直播间的全文实验；角色参考、直播截图和漫画脚本怎样共同约束出图。
每页让观众看到一次明确的状态变化，并用一句结论收束。代码动画并不能代替史料核对、
恰当口播和审片；它的价值在于让因果关系可见。

## 旁白去模板味：先给事实，再让句子自然落地

知乎讨论[「不是……而是」的滥用](https://www.zhihu.com/question/2075603939269895886)指出：这个句式适合纠正同一问题里两个互斥的事实；若只是要说后半句，硬造一个前半句会增加噪音。[果壳对这一口癖的分析（虎嗅转载）](https://m.huxiu.com/article/4883379.html)也指出，凭空预设读者的误解和堆砌抽象转折会挤掉真正的信息。本项目的科普旁白按下面的办法审稿：

- 每段先给一个观众看得见的触发：一次重连留下多个文件、一句被认错的人名、一张画错游戏的漫画。接着说采取了什么处理，最后交代结果或仍然存在的限制。
- 删掉没有真实误解需要纠正的“不是 X，而是 Y”“你以为 X，其实 Y”“真正的关键是 Y”。如果 X 和 Y 确实互斥且这一对比帮助理解，保留一次也无妨。
- 读出声，删掉重复的“我们”“后来”“最终”，把“准确、及时、温柔”等抽象结论落实到对应的检查和时机。每页留一个要点；PPT 只显示关键词，字幕按短句走。
- 不凭空增加事故、收益数字、用户反馈或模型能力；沿着代码、Git 记录和现有审片证据核对事实。

下次生成一页口播可直接用这段提示词，并给模型该页的具体证据：

> 面向第一次接触项目的观众，写 15—25 秒的中文口播。先描述这页的真实场景或出错现象，再说明当时的处理和它带来的变化；保留已知的限制。句子短些，像对朋友解释一次排查经历。删掉无必要的“不是……而是……”“你以为……其实……”和空泛升华；只有实际存在、同一维度的误解需要澄清时才用转折。不要补造事实。最后通读并标出每句对应的来源和画面节拍，删掉来源不明或画面无法承接的句子。

总览页曾因独立 SVG 的文字类未并入主样式而出现深色背景黑字。合成前要在所有页面的开头、关键节拍和末帧检查计算后的文字颜色、对比度、溢出及字幕安全区；查看元素存在或动画推进不足以发现这类错误。

## V4 实作复盘与下次检查

这轮先写全片结构，再把 18 页拆成独立简报和节拍。页面仍需共用配色、字号、
`renderAt({slide,time,duration})` 时钟及旁白时间线，否则逐页产物无法在一部影片里对齐。
目前多数页仍是四个节点依次出现，观众能看出阶段顺序，却不容易看出数据怎么流动、
错误如何出现以及修正后有何变化。下一轮优先重做这种缺少因果变化的页面。

总览页的独立 SVG 嵌入总页面时漏了文字类样式，产生了深色背景黑字。
检查 18 页实际计算后的填充色，才发现问题；这项检查已成为回归测试。
字幕原本压住底部进度线，本轮把字幕底边距调到画高的 18%。
项目的本地配置需设置 `render.subtitle_margin_ratio: 0.18`；框架默认值保持不变。
还要抽帧检查成片，因为浏览器截图无法看见最后烧录的字幕。

改口播后必须重新生成语音、字幕和页面节拍，不能沿用旧声轨。
V4 重新生成了 18 段“乖巧萌妹”TTS，经过 suiV2 +4 转声；源 MP3、转换后 WAV
和 MP4 均保留在被 Git 忽略的 `outputs-v4-pagewise/`。当前的字幕时间是按句段长度
分配到语音时长的近似值；后续要听音校准，语音自然度也仍未达到满意水平。
本地重录时把 `output_dir` 指向 `outputs-v4-pagewise`，并设置上述字幕边距；
通用 `config.json` 的 `output_dir` 可能指向其他目录。

由于音频和视频未纳入 Git，新机器克隆源码后不能直接重渲染 V4。要复现，先按
`project.json` 的 18 段 `narration` 生成“乖巧萌妹”音频，放在每段
`voice.source_audio` 指向的 `outputs-v4-pagewise/tts-raw/<scene>.mp3`；
本地 RVC 配置选择 suiV2，场景的 `pitch: 4` 会在 `voice` 阶段使用。
运行时让本地配置的 `output_dir` 指向 `outputs-v4-pagewise`，并设置
`render.subtitle_margin_ratio: 0.18`。先执行 `voice` 再执行 `record`，
不要用旧音频元数据去配新文案。实际音色结果、字幕时序与积分报价仍随服务端版本变化。
