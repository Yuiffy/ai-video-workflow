# 带鱼转岁己：相似度不足的后续调研

调研日期：2026-10-07。用户最新反馈：第 10 轮、+12 / 索引 0.5 附近的 15 组参数整体仍不够像。此前选择只是相对偏好，不能视为效果验收。保留该组合为比较基准。

## 本地证据与边界

- 两段 OBS 输入是包含带鱼、队友和游戏声的混合音频，不是单独麦克风轨；不能据此断言用户声音不适合转换。
- 已改变音高与索引，尚未在本次对照中验证共振峰调整。
- `outputs/sui-voice-20260928/seedvc/seed_convert.py:31` 明确设置 `convert_style=False`。之前 Seed-VC 对照未覆盖 AR 风格转换，不能据此淘汰该模式。
- 第 10 轮只是已测检查点中的选定候选；四条 TTS 和少量特殊音测试不能证明真实男性输入已达到模型上限，也不能证明继续训练必定有效。

## 网上查证

1. [RVC 官方 FAQ](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/wiki/FAQ-%28Frequently-Asked-Questions%29) Q9–Q11：源音色残留是已知问题；索引权重增加会更偏向训练集，同时可能牺牲音质。训练轮数与数据质量相关，不能统一按 10 或 20 轮断言充分。没有把 FAQ 中的建议轮数直接当作本项目最优值。
2. [Applio 推理文档](https://docs.applio.org/getting-started/inference/)：保留原始措辞节奏和情绪；提供 Quefrency/Timbre 共振峰调整用于跨性别转换。[代码](https://github.com/IAHispano/Applio/blob/main/rvc/lib/utils.py) 实现输入端 formant 处理。共振峰是值得验证的独立变量，不保证改善岁己相似度。该文档的升调方向示例与其自身说明冲突、protect 建议也与代码范围有冲突，不能照抄这些数值。
3. [Seed-VC 官方仓库](https://github.com/Plachtaa/seed-vc)：V2 的 `convert-style=true` 使用 AR 模型进行口音与情绪转换；false 只转换音色。适合补做离线对照，不能将其与 tiny 实时分支延迟混用。官方仓库已于 2025-11-21 归档，并非持续更新的最新框架。
4. [Applio 训练文档](https://docs.applio.org/getting-started/training/) 与 RVC FAQ 均强调干净、音色一致的素材。我们应尝试近时期、同设备的日常说话子集，再验证笑声等特殊发声覆盖；数据少或多本身不是效果保证。
5. [Applio embedder 文档](https://docs.applio.org/getting-started/embedder/) 要求训练与推理使用相同提取器。[Spin 原作者实现](https://github.com/vectominist/spin) 旨在抑制说话人信息、保留内容。作为重新训练的候选，有中文适用性待验证；不能把旧模型推理时直接换提取器当升级。
6. [Zero-VC 作者演示](https://amphionteam.github.io/Zero-VC-demo/) 研究源说话人泄漏与流式转换，但本次未验证可部署代码、权重和本机表现；不据演示直接选为替代方案。

## 建议实验顺序（本轮为调研，尚未执行）

1. 保持 e10 / +12 / index 0.5，补少量输入共振峰变化，并保留不处理版本，比较厚重音色残留、元音与自然度。不要再扩展大量相邻升调档。
2. 同一 Seed-VC checkpoint、同一输入和岁己参考，比较 style off/on；固定随机种子，检查中文错字、节奏和笑声完整性。先用既有参考，之后再单独比较参考风格，避免多个变量混在一起。
3. 追加无队友叠音的普通说话片段；若今后取得 30–60 秒单独麦克风录音，可用于排除混音链路影响。这不是当前调研的前置条件。
4. 若两条推理路线仍不足，再用同设备、同阶段的干净日常说话集重训；按实际步数、真人跨说话人测试与人工听感选 checkpoint。特殊发声单独回归，避免为了普通语音相似度牺牲覆盖。

诊断时分开判断“像岁己”“自然”“保留原话与特殊声音”。源声线与说话方式可能影响难度，但目前没有证据支持“用户天生不能转成岁己”。

## 已执行：共振峰与 Seed-VC 风格对照

用户授权后已完成[试听样例](../outputs/sui-voice-formant-style-20261007/listen.html)：四段输入、40 个转换结果。输入为“别笑”“快跑”“大厅聊天”和单人中文男声对照。大厅仍是 OBS 混音；没有把它标为已验证无叠音或单独麦克风。

RVC 固定 e10 / +12 / index .5 / protect .15，比较输入共振峰 ×.9/1.1/1.2/1.3，并包含无共振峰处理、STFT ×1.0 控制组和旧页原始基准。Seed-VC 比较同一参考与 CFM step1000 的风格 off/on，以及额外的保守采样。此次没有重新训练模型。

44 条输入/转换 WAV 已验证可解码、非静音、数值有限；页面链接与 JS 语法检查通过。16 条自动转写只作诊断，不是人工真值或 CER。保守采样的“别笑”存在明确时长异常：8 秒生成约 28 秒，页面已标为异常且不推荐。未依据机器指标宣布新方案胜出。完整参数、来源、哈希、自动转写与脚本均随样例保存。

## 最新用户试听反馈

用户反馈“seedVC转换风格感觉很像哦，只换音色也有点像”；认为共振峰 ×1.2 可能比 ×1.1 更像，但区别不大。后续优先候选改为本次 `seed_on`，保留 `seed_off` 作对照；RVC ×1.2 只是较弱、带不确定性的偏好，不继续优先扩展共振峰网格。

该反馈说明当前转换方案对结果影响很大，不能归结为用户声线不适合。尚不能据听感单独区分风格迁移、源音色抑制及其他架构差异的贡献。下一步重点是扩展真实输入上的内容保持、笑声和激动声音稳定性，而非再次微调 RVC 升调。精确参数与原话已保存到试听目录 `listening-feedback.json`；Seed-VC 优先候选不包含 RVC 的 +12 或共振峰 ×1.2 预处理。
