# 中文视频配音：TTS 与变声器选型调研

调研日期：2026-10-07。场景：本仓库的中文技术解说、角色口播与固定岁己音色；本机实查为 RTX 5080 / 16GB。

2026-10-13 更新：Fish Speech S2 Pro 已在本机以 BF16 原始权重、4K 上下文和分阶段 codec 完成中文与岁己克隆测试，用户试听反馈“感觉不错”，现作为 `provider=fish` 纳入本地配音选项。下面的官方 24GB 建议仍适用于默认部署；本机短句运行不代表 32K 长文或流式服务通过。详见 [实测与安装记录](fish-speech-local-20261013.md) 和 [配音工作台](voice-studio.md)。

## 建议

将**直接音色克隆 TTS**作为下一版旁白的优先路线。首轮比较 **MiniMax Speech 2.8 HD、IndexTTS 2.5、VoxCPM2**；追求固定角色的长期相似度时，再试 **GPT-SoVITS 定制训练**。保留已有新版 RVC 和定制 Seed-VC，服务于“已经有人把这段话演好了，需要换音色”的场景。

这是基于官方能力、硬件、接入条件和仓库已有实验的选型优先级，**不是本轮听感盲测排名**。本轮没有生成新音频、安装模型或完成真人试听；不能宣称某个新模型已经在岁己素材上胜出。

- 视频版本不能直接套用：官方 IndexTTS 已于 2026-08-10 发布 2.5；GPT-SoVITS 当前 README 也有 V5 升级说明。选择时应记录实际代码和权重版本。

## 当前工作流的瓶颈

1. **RVC 主要改变音色，不能指望它补出底层口播没有的语气和表达。** 固定音色 TTS 的停顿、重音、语速问题通常会带入转换结果，转换还可能引入金属感、辅音损伤和音高不匹配。这里是机制上的风险判断，本轮没有对成片作新的听感归因。
2. **自动 TTS 分句过碎是需要对照验证的因素。** `src/voice.py:phrases()` 按逗号等标点切分，再将片段限制在约 32 字符，逐片生成后拼接。这可能导致句中语气反复重置。V4 使用外部整段音频的场景不走这条自动分句路径，不能把所有既有听感问题都归因于它。
3. **不要再把旧 suiV2 +4 当成唯一基线。** [既有重制记录](sui-voice-rebuild.md)已交付新 RVC 第 10 轮模型 `sui_v3_48k.pth`（底层仍为 RVC v2）和定制 Seed-VC。四段开发样本上，新 RVC 与同参数旧模型相比，平均声纹相似度 0.7195 → 0.7714，平均 CER 9.43% → 5.40%。这不是盲听成绩或独立测试成绩，但足以要求新选型用更合理的现有基线。
4. **直接克隆已有先例。** [9 月实验记录](dreamina-audio.md)表明，MiniMax 网页已用过 `speech-2.8-hd` 和已有克隆音色，即梦网页也有“岁己1”。当时 Canvas CLI 的固定音色限制不能推广到即梦网页或所有 Seed TTS 产品。网页音色是否能被 API 直接复用尚未核实。

## 候选比较

下表“优先级”表示本项目测试价值；官方宣称的自然度、相似度和速度不能代替我们的对照样例。

| 方案 | 已核实的能力 | 本项目判断与限制 |
| --- | --- | --- |
| **MiniMax Speech 2.8 HD** | 云端直接克隆 TTS；API 有语速、音高、情绪、读音词典及字幕相关字段；提供长文本异步接口 | **最快落地的生产候选**。已有网页克隆实验，适合先做整章中文旁白对照。网页与 API 账号、音色、额度不要假定互通；长文自然度仍需实测。 |
| **IndexTTS 2.5** | 分离音色参考与情绪参考；情绪强度、八维情绪向量；中文拼音/英文音素控制；`duration_factor` 控制 0.5–2.0 倍时长 | **本地情绪口播首测**。比继续依赖固定音色 TTS → RVC 更贴合需求。Windows 可跳过 DeepSpeed；没有本机峰值显存和速度实测，16GB 是否满足所选参数需跑样例确认。2.5 的语速控制不等于保证任意精确秒数。 |
| **VoxCPM2** | 2B；中文在内的 30 种语言；参考音频克隆、风格指令、参考音频加转写的延续生成；48kHz 输出；官方表列约 8GB 显存 | **第二个本地直接克隆候选**。硬件条件适配，便于验证轻情绪和自然口语。48kHz 与架构名称本身不证明听感优越。 |
| **GPT-SoVITS** | 少样本克隆、定制训练；当前 README 同时说明 v2Pro 系列与 V5，V5 升级指向专门分支和权重 | **长期固定岁己音色的训练候选**。可利用已有数据清理成果，但仍需适合 TTS 的准确转写与分段；RVC `.pth` 不能直接加载成 TTS。先验证 V5 零样本和适用训练流程，再与成熟 v2Pro 路线比较，不默认版本号越大越好。 |
| **Fish Audio S2 Pro** | 4B 主干；细粒度情绪/发声标签、多角色对话、短参考音频克隆 | **云端质量对照优先**。官方推理文档建议至少 24GB 显存，本机 16GB 不宜当作默认原精度部署目标；量化/卸载另测。发布权重是研究许可，商业使用另需许可。 |
| **Qwen3-TTS** | 0.6B / 1.7B；Base 做参考音频克隆，CustomVoice 做预设音色，VoiceDesign 做文字设计；提供微调流程 | 有价值的备选，但**任意声音克隆与指令情绪控制不能直接视作同一模型能力**。1.7B Base 的官方模型表没有将其标成与 CustomVoice 相同的指令控制模型；需明确测哪个 checkpoint。 |
| **dots.tts** | 2B 连续语音生成；当前有 SOAR、MeanFlow、固定步数及独立语音编辑模型；代码和权重 Apache-2.0 | 第二轮自然度/局部修音候选。官方在不同长度下报告约 5–11GB 显存，依赖具体版本和设置；不能把别的 GPU 上的速度当成本机成绩。视频的 6 月样例不代表后续加速和编辑模型。 |
| **MOSS-TTS v1.5** | 8B 主模型，长语音、拼音/音素与显式停顿控制；另有 4B Local v1.5、Nano 等独立模型 | 长文或多角色时值得再测。8B 常规半精度权重已接近本机全部显存，需给编解码器和缓存留余量；官方有 llama.cpp 量化/分阶段加载路线，不能简单说 16GB 跑不了，也不能混用各变体质量结论。 |
| **OmniVoice** | 多语言零样本克隆和音色设计，覆盖 600+ 语言；可指定时长/语速 | 多语言覆盖不是我们当前主要短板，首轮优先级较低；不据此判断中文效果差。 |
| **CosyVoice 3** | 中文等多语言零样本、流式合成与指令控制；0.5B 级模型 | 适合作为以后本地服务、低延迟场景备选；当前离线角色旁白优先解决情绪与相似度。 |
| **ElevenLabs** | 当前官方文档列 Eleven v4，支持中文、情绪对话与克隆，入口为 Text to Dialogue API；另有中文可用的 Multilingual STS v2 变声 | 可做云端对照，但已有 MiniMax 路径，先比较更贴合现有中文流程的候选。本轮未核定套餐费用或验证中文岁己样例，不作音质高低断言。 |

## 变声器怎么选

- **现有新 RVC：** 保留为基线、低延迟及需要保留输入音高走势的候选。换 Applio 等 RVC 前端不等于更换核心模型，也不能自动解决听感。
- **定制 Seed-VC：** 已有模型值得复用，适合离线口语换音色。但之前六条特殊声音的重建测试中，定制 Seed-VC 的大幅音高变化明显多于 RVC；不能直接推广到笑声、尖叫或唱歌。指标详见重制记录。
- **ElevenLabs Voice Changer：** 若有真人录好的表演，可与前两者做同源音频对照。它是语音到语音接口，和 Eleven v4 的文字配音接口是两条路线。

因此：**从文字做旁白，先直接克隆 TTS；从已经满意的真人表演做换声，再比较 VC。** 不默认给优质克隆 TTS 再串一次 RVC。

| 项目 | 刊例价 |
| --- | --- |
| Speech 2.8 HD，同步/异步 | 3.50 元 / 万计费字符 |
| Speech 2.8 Turbo，同步/异步 | 2.00 元 / 万计费字符 |
| 快速复刻音色 | 9.90 元 / 音色，首次合成使用时计入；试听另按所选模型计费 |

**1 个汉字计 2 个字符**，英文字母、标点、空格、换行等各计 1 个。以 2500 个纯汉字估算，HD 一次约 **1.75 元**，Turbo 约 **1.00 元**，实际再计标点、重试及可能的首次音色费用。这不是 MiniMax Audio 网页订阅报价，也不能与 Dreamina 积分按数值比较。

本地 TTS 没有按字符 API 账单，但需要下载、环境维护、显存和生成时间。IndexTTS 当前采用 bilibili Model Use License Agreement，并非 MIT/Apache；VoxCPM2、dots.tts 的官方说明为代码与权重 Apache-2.0；Fish S2 Pro 的发布权重许可不授予商业权利。这些差异应纳入长期选型，不影响先进行本地非商业评估。

## 下一次实验的具体方案

**第一轮不训练大模型：** MiniMax 2.8 HD、IndexTTS 2.5、VoxCPM2，加旧 V4 成片音频、新 RVC 作为对照；即梦网页已有“岁己1”直接合成也应作为低接入成本对照。不要把 Canvas 固定音色当作即梦全部能力。

1. 从可用目标音频选中性、轻开心、轻吐槽三个干净参考，避免配乐、叠人声、长静音和强降噪伪影。各模型优先使用同一来源片段，必要的长度差异如实记录，不强迫不同模型使用不合规格的输入。
2. 固定 12 条文本：普通叙述 3 条；Codex、Webhook、Whisper、FunASR、RVC 等专名及中英混读 3 条；疑问、轻吐槽、温柔收尾 3 条；数字日期、多音字和长句转折 3 条。再测一段 60–90 秒连续技术解说。
3. 小样先比较原生克隆，不升调、不接 RVC。IndexTTS 分别测试同参考默认情绪与低强度情绪控制；不只挑一次最好听的输出。
4. 每条用相同次数生成，例如 3 次；分别记录一次成功率、重复/漏读/错读、音色漂移与挑选后的最佳结果。统一输出播放响度，不通过降噪把某个模型单独修得更好。
5. 盲听分别记录自然度、目标音色相似度、情绪恰当性、文字准确性、跨句稳定性。按 5 分制；建议先以自然度 30%、相似度 25%、准确性 20%、稳定性 15%、情绪 10% 加权。长篇解说不以情绪越强越好。
6. ASR CER、声纹相似度只做辅助；同时记录峰值显存、首次加载时间、热运行生成时间、实际费用。不要用 ASR 正确替代好听。
7. 若直接克隆的语气满意、但岁己音色不足，再进入 GPT-SoVITS 定制训练，先整理一小批高质量精确转写数据验证，不把全部旧 VC 训练音频直接投入。

**推荐默认分工：** MiniMax 作为尽快生产的候选；IndexTTS 2.5 作为本地情绪口播候选；VoxCPM2 作为第二个本地候选；GPT-SoVITS 留给长期角色定制。实际默认引擎由上述同文盲听决定，而非这个调查表直接宣布。

## 与仓库的接入方式

- 试验可先将外部生成 WAV 通过 `voice.source_audio` 接入，确认是目标输出后设置 `voice.already_target_voice: true`；现有代码会跳过 RVC，成本最低。
- 若自动接新 TTS，需要把引擎、模型/权重版本、音色 ID 或参考文件哈希、风格、随机种子记录到缓存元数据。云端任务保存请求与计费状态，避免未知结果时盲目重试。
- 新版生成单元建议先试完整句子或短段，保持语言上下文；字幕改用生成后的实际对齐。当前外部音频字幕是按文本长度估算，不能把旁白换模型等同于字幕自动变准。
- 5080 环境使用已验证支持该 GPU 的 PyTorch/CUDA 组合。各模型独立环境、逐个加载，避免修改原 RVC 运行环境。
